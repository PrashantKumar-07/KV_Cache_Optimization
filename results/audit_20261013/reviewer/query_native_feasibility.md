# Current-query selection on the native CPU controller: feasibility

Read-only review; no source edits/GPU experiments. **Feasible as a narrow opt-in adapter, but existing QuerySelector cannot be enabled by removing its parser guard.** Support only serial batch1, single-token Mistral BF16 decode, eager attention feedback, full prefill, no sliding-window/cache quantization. Native integration and quality/performance remain unproved.

## Concrete incompatibilities and existing reuse

`evaluate_query_selection.py:205-206` forbids `--cpu-batched-scores` outsideLRU because that switch changes storage to CPU as well as score batching. QuerySelector (`:85-126`) directly indexes `cache.stt_k`, assumes GPU tensor access, independently repeats q_proj and builds dense concatenated layer.keys/values. CPU slot `stt_k` is a diagnostic property (`cpu_slot_cache.py:49-72`): it synchronizes and materializes logical keys on CPU; GPU q versus these CPU keys fails einsum. A naive `.to(cuda)` would add unaccounted full scans. Dense replacement also loses native reserved hot-root ownership and append spare: `shared_decode_transition.py:10-25`, `cpu_phase_policy.py:167-182`, `reserved_decode_append.py:19-39`. QuerySelector updates positions only; stale indices currently trigger safe position-lookup fallback in ordinary/batched feedback, but a native adapter must update both.

Score batching itself is not fundamentallyLRU-only. `batched_score_policy.py:14-66` supports equal hot/cold widths and ordered hot prefix; it validates selected index→position identity, then records `_stt_attn` by position and `_stt_attn_idx` by logical index. `native_controller_policy.py:116-125` consumes those dictionaries for subsequent promotion. Current cold exposure (`cold_boundary.py:40-98`) uses canonical CPU live/slot/version planes, ranks recency timestamps, fetches KV and scatters into the shared root cold tail. Canonical state must not be mutated by a query selector.

Reuse existing `PoolQuerySelector` (paired storage delivery and both metadata fields), `SuffixQuerySelector`/`replace_cold_suffix` (in-place root-preserving tail), `ChannelReader`/`write_selected_values` (full K-only scan and selectedV), and `GpuLiveReader` (live logical→physical map validity and manager event/flush ordering). These are research prototypes, not current default integration. `ChannelQueryPolicy` inherits olderBulkPromotionPolicy, not currentColdBoundaryPolicy; do not combine them with speculative multiple inheritance. Explicit current-policy reader lifecycle is smaller and auditable.

Historical `results/hardware/query_channel_reads_v1/verified_cost.json` rejects standalone channel expansion:97.48→93.02ms,4.57% versus required5%. Preserve that failed gate. A new prototype must name its changed hypothesis/current backend/projection reuse rather than retry the old candidate for favorable timing.

## Minimal opt-in interface

Use a separate `NativeQueryTailLease(model, policy, reader)` in a new diagnostic runner initially. Attach `ChannelReader` to currentColdBoundaryPolicy through explicit initialization, refresh after every completed `_visible_tuple`, and close before policy reset/arena teardown. Use an attention pre-hook only to capture layer kwargs/currentcos,sin and validate supported shape/visibility; an actual `q_proj` output hook obtains the already computed projection, computes the same BF16 RoPE expression, then float/GQA reshape as existing selector. Preserve projection output; returnNone. Current installed Mistral executes q_proj before k_proj/v_proj and DynamicLayer.update, so selection can finish before append. Clear per-layer context after forward and on exceptions; install hooks with rollback, guarded creation and unconditional cleanup. This avoids duplicate q/k linear projections; RoPE multiplication for selection still duplicates a small operation unless attention itself exposes postRoPEq.

For each layer, freeze live-map/version; rank exactly existing global-head query score on hot prefix+all live cold keys; choose exactly the prepared cold width, sorted logical indices with the same topk/tie semantics. Read selectedV and copy selectedK from the already scanned tensor into `[hot:hot+quota]`. Change **no** root, stride, visible length, hot prefix, current append spare, allocator owner or canonical slot plane. Atomically publish `_vis_stt_idx[layer]` and `_vis_stt_pos[layer]` matching the actual copied payload; retain `_vis_sram_keep`, `_vis_len`, uniform per-layer widths. Reject stale version, overlapping sources/destinations, absent prepared tail, extra/missing rows, foreign pool/device, missing native owner or unsupported shapes before writes. If live≤quota, retain already exposed payload/identity and skip scanning. Do not invent unobserved attention feedback for unexposed candidates; normal forward weights update selected rows only.

## Traffic and resource boundary

Current recency visibility has already fetched the old32 KV rows before a current layer query exists. A minimal adapter incurs that wasted read plus full liveK scan plus selectedV fetch, and the layers execute sequentially. At full2048live×8KVheads×128dims×BF16×32layers, full K scan is128MiB per token, selectedV32 is2MiB, and preexisting recencyKV32 is4MiB. Actual live counts can be smaller; bill observed events, not maximum capacity. Using paired full reads instead is256MiB; selectingK from scanned keys avoids another selectedK fetch. Descriptor/index copies, flush writes, GPU staging/float logits, query computations, kernel launches and synchronization also count. Existing policy's selectedKV analytical read bill alone does not account retrieval traffic; keep actual copied payload counters separate and add explicitly modeled retrieval events without double charging reused selectedK. Query-to-CPU scoring is an alternative with CPU fullK reads and query/normalizer transfers, not a free zero-copy equivalent; treat it as another mechanism, not the default prototype.

## Required proof before a real run

CPU probe `query_native_projection_probe.py/.json` passes tiny2-layer BF16 Mistral projection equality and order attention-pre→actualq-projection→cache-append; in-place cold-tail replacement preserves reserved append/hot bytes while dense concatenation forces fallback. This establishes mechanics only.

Additional oracles: adapter logits/payload/selected-position parity against existingGPU QuerySelector on same frozen single-token queries; both metadata index dictionaries point to actual copied rows; feedback/next-step promotion agrees with position-lookup reference; hot/cold owners and append spare remain identical; native version guards, shadows, physical slot permutes, empty/live≤quota, tied scores, reclamation and layer-width minimum are covered. Inject failures at hook registration, read, validation, scatter and model forward; require leases/hooks/roots closed and reject reuse of partial mutation without reset. Then a distinct preregistered small current-native full-model parity gate, observed per-channel traffic/peak resources, and fair timing screen. No speed or quality advantage is inferred from feasibility.
