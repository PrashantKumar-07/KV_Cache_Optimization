# TieredKV literature and evidence audit (13 October 2026)

This note supports `paper/paper.tex`. The intended scope is a simulated STT-like slow tier in Python plus a separate measured CPU-DRAM implementation. A physical STT-MRAM device is **not required** to complete that simulated study. The paper must keep the simulation's assumptions and the CPU prototype's measured outcomes separate. The old `figures_final/` pack mixes September inputs; current October CPU figures should be generated from frozen raw rows and hashes.

The September simulation quality records and October CPU control rows belong to different implementations and experiments. No current CPU-quality score is established. The older task-balanced intervals are conditional on selected examples, tasks, model, and seed. TriviaQA target identity uses `input` while `context` contains demonstrations; a document exclusion based on `context` cannot establish target independence. Prior fresh100 selections reuse development targets. The manuscript therefore avoids independent-holdout language.

The current ordinary/native cold path exposes cold rows by recency and promotes them using observed attention after exposure. It does **not** search every cold key with the current query. Simulator sketch/query language must never describe the measured native path. A new code audit also found that bounded prefill can reset absolute token identities and that multi-query score fallback can omit score updates; existing parity on tested single-token paths is narrower than general correctness. These defects are under repair elsewhere and no repaired result is presumed here.

## Closest prior work and comparison role

| Primary source | What it establishes | Use in this paper |
|---|---|---|
| [SnapKV (Li et al., 2024)](https://arxiv.org/abs/2404.14469) | Observation-window, per-head prompt KV compression. | Historical in-harness adaptation in the simulated study; a separate faithful selector adapter is the CPU timing baseline. Do not mix those labels. |
| [H$_2$O (Zhang et al., 2023)](https://arxiv.org/abs/2306.14048) | Heavy-hitter/recent-token dynamic eviction. | Background and historical compressed control. |
| [StreamingLLM (Xiao et al., 2023)](https://arxiv.org/abs/2309.17453) | Attention sinks and recent window for streaming inference. | Historical background/control only. |
| [Quest (Tang et al., ICML 2024)](https://proceedings.mlr.press/v235/tang24l.html) | Scores page min/max key metadata against the current query to choose sparse attention pages. | Query-aware selection is prior art; evaluation methods differ. |
| [RetrievalAttention (Liu et al.)](https://arxiv.org/abs/2409.10516) | CPU approximate nearest-neighbor retrieval for relevant KV. | Relevant retrieval-system comparator; no local matched result. |
| [RocketKV (Behnam et al., ICML 2025)](https://proceedings.mlr.press/v267/behnam25a.html) | Two-stage GPU KV compression and sparse attention with GQA-aware components. | Newer compression context, especially if claiming quality/latency SOTA. |
| [FlexiCache (Takbir et al., MLSys 2026)](https://proceedings.mlsys.org/paper_files/paper/2026/file/94bcb01789fccf15afe2764d8fe0f40e-Paper-Conference.pdf) | Stable heads keep full KV on host and top pages on GPU. Section 3.3 says each stable-head page is offloaded exactly once; later promotions read the host copy. | Closest host-retaining system. Inclusive shadow/avoid-repeat-write is not novel in broad principle. Its vLLM throughput/online latency is not directly comparable to this fixed-request harness. |
| [IceCache (Mao et al., ICLR 2026)](https://arxiv.org/abs/2604.10539), [official code](https://github.com/yuzhenmao/IceCache) | Query-aware retrieval of CPU-resident KV pages using dynamic indexing; LongBench runner. | Direct CPU-offload comparator after common prompt, model, precision, score, resource, and software stack checks. |
| [DirectKV (Luo and Shen, OSDI 2026)](https://www.usenix.org/conference/osdi26/presentation/luo) | Direct CPU KV access over NVLink-C2C on GH200/GB200, eliminating GPU staging. | Systems context; different link/hardware, so no numeric cross-system comparison. |
| [FlexGen (Sheng et al., ICML 2023)](https://proceedings.mlr.press/v202/sheng23a.html) | Early GPU/CPU/disk offloading and I/O scheduling for high-throughput LLM inference. | Broad tiering prior art, not a direct token-retention control. |

The benchmark source is [LongBench (Bai et al., ACL 2024)](https://aclanthology.org/2024.acl-long.172/). [NVIDIA's L40S page](https://www.nvidia.com/en-us/data-center/l40s/) specifies 864 GB/s GPU memory bandwidth. [Everspin's PERSYST release](https://investor.everspin.com/news-releases/news-release-details/next-generation-ibm-flashcore-modules-feature-everspins-persyst) reports 2.7 GB/s read **and** write for one 1-Gb part. It does not substantiate a 50/12.5 GB/s GPU-visible STT tier or a 4x read/write asymmetry. The model's 2/8 pJ/bit STT and 12 pJ/bit GPU energy values remain assumptions.

## Submission boundary

The present evidence can support a two-column design/simulation and CPU-engineering paper if it presents the simulation as a sensitivity study and the CPU results as a negative faithful-baseline finding plus same-policy improvements. It cannot support a SOTA quality/latency headline, actual STT energy/endurance, or an independent quality claim. A physical STT device would be needed only for claims about physical STT behavior; it is not a prerequisite for a clearly labeled simulated-tier study. To strengthen the simulated study itself, rerun quality and policy counters over independent target identities, more seeds/models, and declared bandwidth/energy ranges, then compare complete measured GPU/CPU loops under common inputs and resource envelopes where a systems claim is desired.
