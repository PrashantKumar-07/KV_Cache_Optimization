# Model integration boundary

Standalone phase passes; integration remains unimplemented. Reference decisions are supplied. Current full-model baseline/quality/memory requirements are still open.

1. Preserve `CpuPhasePolicy._prepare_decode_reads()` CPU ownership, selection, versions and planned promotions. Its promotion KV copies can initially remain charged. Build bulk states after the parent prepares all native demotion commands: old KV then already includes promoted rows; pass empty promotion tensors and the current raw new-token views. Metadata inputs must span old+promoted+new; GPU cold prefix spans previous timestamp length plus paid count. Exclude cold-overflow/reclaim cases initially by preserving the existing CPU-phase fallback.
2. Apply the bulk helper only after all descriptors/layouts qualify, before per-layer metrics. Keep native CPU commands live until each cache consumes them. Replace only the already-executed payload/metadata part of eviction; keep promotion accounting, `_t`, metrics, returned demoted/paid/restored counts, CPU versions/positions/FIFO and unsupported fallback unchanged. Avoid the ordinary new-token F32 roundtrip only while the fused phase has applied its exact conversion. Empty hot payloads require ordinary caller fallback.
3. Queue the exact packed paid GPU tensor for one shared-pool native D2H dispatch. Preserve pending-write order, destination physical slots, CPU allocation, native submitted bytes/calls, contributor counters, stream events and buffer lifetime. Flush before any later enqueue/read/reset/close. Zero paid rows must produce no dispatch. CPU physical addresses and conflict handling were excluded from both primitive screen arms and must be charged in the model run.
4. Rebind hot KV/metadata and timestamps to existing owned prefixes; consume pending keeps and count the group8 compactions once. Do not compact a second time through inherited visibility. Keep current root geometry and metadata owner accounting; actual model peaks are unproved until a fresh audit.
